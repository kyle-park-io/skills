# systemd-timer

**골격형.** `skeleton/` 은 복사해서 쓰는 파일이 아니다. 복사해도 안 돈다.

> **마지막 검증**: 2026-09-09 에 `mantle-kr-herald` 에서 뽑음. **다른 머신에 세워본 적 없다.**
>
> 골격형이라 파일 자체는 덜 썩는다. 다만 결정 2 (nvm 이 버전 디렉터리를 지운다) 와 결정 6 (journald 가 시계 역행에 로테이트한다) 는 **도구와 플랫폼의 동작에 의존한다.** 근거가 아직 참인지 대상 머신에서 확인한다.

`systemd --user` 타이머로 주기적 작업을 돌리는 레포용. 이식되는 것은 파일이 아니라 **결정 여섯 개**다.

## 왜 골격형인가

원본 유닛 파일이 스스로 이렇게 적고 있다.

> Machine-specific by design, not templated: a different machine needs its own copy of this file with its own paths, not a parameterised one.

절대 경로, 호스트별 인터프리터 위치, 그 머신에서만 참인 타임스탬프가 박혀 있다. 플레이스홀더로 치환하면 **이식 가능해 보이는데 실제로는 아닌 파일**이 되고, 그게 더 나쁘다. `skeleton/` 의 파일들은 골조와 근거만 남긴 것이고, 대상 머신용 파일은 그걸 보고 새로 쓴다.

## 출처

`mantle-kr-herald` `deploy/` (`herald-watch.service`, `herald-watch.timer`, `herald-notify-failure@.service`). 아래 사고 기록은 전부 그 파일들의 헤더 주석에 있다.

## 여섯 개의 결정

### 1. 실패 알림은 템플릿 유닛을 거친다

systemd 의 `OnFailure=` 는 **유닛만 지정할 수 있고 스크립트를 직접 못 쓴다.** 그래서 알림 스크립트는 래퍼 유닛을 통해 돈다.

그 래퍼를 **템플릿(`@.service`)으로** 만드는 게 두 번째 결정이다. 고정 유닛으로 두면 스크립트 안에 유닛 이름을 하드코딩하게 되고, 그 훅을 공유하는 두 번째 스케줄러가 생기는 순간 **엉뚱한 유닛 이름을 보고하고 엉뚱한 저널을 tail 한다.** herald 에서 실제로 일어났고 그래서 템플릿이 됐다.

```
OnFailure=notify-failure@%n.service
```

`%n` 은 `OnFailure=` 타겟이 해석되기 **전에** 실패한 유닛 자신의 이름으로 확장된다. 그 이름이 템플릿의 `%i` 가 된다. `man systemd.unit` 의 `OnFailure=` 예제에 있는 관용구 그대로다.

### 2. 인터프리터는 심볼릭 링크 디렉터리를 경유한다

systemd 유저 유닛의 기본 PATH 에는 `node`, `pnpm` 같은 게 없다. 그렇다고 nvm 경로를 직접 쓰면 안 된다.

**nvm 경로는 버전을 들고 있다** (`.../v24.14.0/bin`). nvm 은 업그레이드할 때 그 디렉터리를 지운다. 그 경로를 쓴 유닛은 다음 fire 에서 한 줄도 못 돌고 `203/EXEC` 로 죽는다. 타이머는 계속 돌고, 매번 똑같이 실패하고, 유일한 신호는 실패 알림뿐이다.

herald 에서 2026-08-09 머신 재구축 때 정확히 이게 났다. 박스가 v24.19.0 으로 돌아왔는데 유닛 세 개가 전부 v24.14.0 을 가리키고 있었다.

대신 직접 관리하는 심볼릭 링크 디렉터리를 둔다. 업그레이드 후에는 링크만 다시 걸고 유닛은 건드리지 않는다.

```bash
mkdir -p ~/.<app>/bin
ln -sfn "$(which node)" ~/.<app>/bin/node
ln -sfn "$(which pnpm)" ~/.<app>/bin/pnpm
```

인터프리터가 절대 경로로 불려도 PATH 는 여전히 필요하다. `pnpm` 파일 자체가 `#!/usr/bin/env node` 로 시작하고, `env` 는 `ExecStart=` 의 경로가 아니라 이 PATH 로 `node` 를 찾는다.

### 3. 스케줄러는 배포 체크아웃에서 돈다

`WorkingDirectory=` 가 **개발 트리를 가리키면 체크아웃한 브랜치가 곧 프로덕션이다.**

herald 에서 2026-08-07 에 아직 머지 안 된 브랜치가 체크아웃돼 있었고, 그 브랜치가 추가한 컬럼을 18:41 fire 가 조회했다. 프로덕션 DB 에는 없는 컬럼이라 non-zero 로 죽고 실패 알림이 울렸다. **브랜치에는 아무 문제가 없었다.** 머지가 안 됐을 뿐이다.

별도 체크아웃(`~/.<app>/app`)을 두고 배포 스크립트로만 갱신한다 (fetch, `origin/main` 으로 hard reset, install, migrate).

이건 **실패 훅에서 더 중요하다.** 스케줄러가 미머지 코드를 돌면 시끄럽게 실패하지만, 실패 훅이 미머지 코드를 돌면 조용히 실패한다. 그 훅이 하려던 말이 "뭔가 실패했다"였기 때문이다.

### 4. `TimeoutStartSec` 는 타이머 주기보다 충분히 작아야 한다

바운드가 없으면 먹통이 된 실행이 유닛을 영원히 `active` 로 남긴다. 그리고 **systemd 는 유닛이 아직 active 이면 다음 타이머 fire 를 스킵한다.** 결과는 무장된 것처럼 보이는데 조용히 멈춘 스케줄러다.

상한도 같은 이유로 중요하다. herald 는 두 시간 주기(7200s)에 1800s 를 썼다. 4배 여유다. 이 값이 주기에 가까워지면 먹통 실행 하나가 다음 fire 를 잡아먹는다.

숫자를 유닛 안에 산술로 적는다. herald 는 이렇게 적어뒀다: 에이전트 호출 2회 x 600s + 나머지 네트워크·DB 호출 600s = 1800s.

### 5. 스케줄러의 산출물 트리를 분리한다

스케줄된 실행과 손으로 돌리는 로컬 실행이 **워터마크나 상태 파일을 공유하면 안 된다.**

herald 에서 개발 DB 로 한 번 돌린 게 공유 상태 파일을 39개 스레드만큼 밀어버렸고, 프로덕션 실행은 그 39개를 영원히 건너뛰게 됐다.

`<APP>_OUTPUT_DIR` 같은 환경변수로 스케줄러 전용 경로를 준다. 절대 경로로 해석되게 한다.

### 6. 저널은 기록이 아니다

journald 는 **시계가 뒤로 갈 때마다 로테이트한다.** WSL2 는 호스트 동기화와 timesyncd 가 시계를 계속 밀어서, herald 의 머신에서 읽을 수 있는 창은 약 8분으로 측정됐다. 02:17 에 성공한 tick 이 같은 날 03:30 에 복구 가능한 줄이 하나도 없었다.

그러면 "tick 은 성공했는데 엉뚱한 일을 했다"에 증거가 아예 없다. 그리고 4번의 타임아웃은 **그것이 죽인 실행의 로그가 유일한 진단 수단**이다.

그래서 `ExecStart=` 를 로깅 래퍼로 감싸 별도 런 로그를 남긴다. 주의할 점 두 가지가 있다.

- `StandardOutput=append:` 를 대신 쓰지 않는다. 저널에 **더하는** 게 아니라 **대체한다.** 실패 훅이 저널에서 뽑는 발췌가 사라진다
- 래퍼가 tick 의 종료 코드를 그대로 넘겨야 한다. non-zero 를 삼키는 `| tee` 하나가 실패 알림을 영구히 꺼버린다

## 대상 머신에서 할 것

1. `skeleton/` 을 읽고 여섯 결정 중 어느 게 필요한지 고른다
2. 대상 머신에서 인터프리터 경로를 **직접 찾는다** (`command -v`). 골격의 경로를 믿지 않는다
3. `~/.<app>/bin` 심볼릭 링크 디렉터리를 만든다
4. 배포 체크아웃을 만들고 배포 스크립트로 채운다
5. 유닛 파일을 새로 쓴다. 골격의 주석 중 그 머신에서 참인 것만 옮긴다
6. **순서 주의**: `ExecStart=` 가 가리키는 래퍼 스크립트가 배포 체크아웃에 들어간 뒤에 유닛을 `~/.config/systemd/user/` 로 복사한다. 반대로 하면 다음 fire 가 없는 파일을 실행한다
7. `systemd-analyze calendar '<OnCalendar 값>'` 으로 일정을 검증하고 출력을 기록에 남긴다

## 안 써도 되는 조건

- **호스팅된 스케줄러를 쓴다.** GitHub Actions `schedule`, Vercel Cron, 클라우드 스케줄러를 쓰면 1~6 전부 무의미하다. 이 조각은 내 머신에서 도는 스케줄러 전용이다
- **`systemd --system` 이다.** 유저 유닛이 아니면 `%h` 도 PATH 문제도 다르게 풀린다. 2번과 3번은 여전히 참이지만 형태가 달라진다
- **컨테이너 안에서 돈다.** 이미지가 인터프리터 경로를 고정하므로 2번이 사라진다. 배포 체크아웃도 이미지 태그가 대신한다
- **작업이 1분 안에 끝난다.** 4번의 산술이 사소해진다. 나머지는 남는다
- **WSL2 가 아니고 시계가 안정적이다.** 6번의 근거가 약해진다. 그래도 저널 보존 기간은 확인하고 뺀다
