# 접근성 패스

자동 검사 결과만으로 통과를 선언하지 않는다. 정적 규칙, 키보드 사용, 실제 상태
변화를 함께 확인한다.

## 범위 고정

검토할 경로와 대표 상태를 먼저 정한다. 기본 화면뿐 아니라 로딩, 빈 상태, 오류,
검증 실패, 모달, 작은 화면처럼 이번 변경이 만든 상태를 포함한다.

## 확인할 것

- 레포에 있는 접근성 검사와 브라우저 테스트를 실행하고 새 위반과 기존 위반을
  구분한다.
- 키보드만으로 주요 작업을 끝내 본다. 포커스 순서와 표시, 열고 닫을 때의 이동과
  복귀, 건너뛰기 링크와 키보드 함정을 확인한다.
- 네이티브 요소를 우선하고 접근 가능한 이름, 레이블, 오류 연결, 제목 계층,
  랜드마크, 이미지 대체 텍스트가 실제 의미와 맞는지 본다.
- 색만으로 상태를 전달하지 않는지, 텍스트와 포커스 표시의 대비, 확대와 리플로,
  모션 감소 설정을 확인한다.
- 비동기 갱신과 오류가 보조 기술에도 전달되는지, 비활성 상태와 로딩 상태가
  조작 가능성에 대해 거짓 신호를 주지 않는지 본다.

공유 프리미티브가 원인이면 그 소유 지점에서 고치되, 이번 검증과 무관한 전면
리팩터링으로 넓히지 않는다. 수정 뒤 같은 상태를 다시 검사한다.

## 보고

검사한 경로와 상태, 자동 검사 결과, 직접 확인한 키보드 흐름, 고친 문제와 남은
문제를 적는다. 자동화가 잡지 못하는 항목을 확인하지 않았다면 그 한계를 명시한다.
